# SESSIONS

Task-tracking breakdown of the PhoWhisper pipeline build, split into units small enough for one Claude Code session each. This file changes constantly as work progresses — for the stable spec (module contracts, data flow, config schema, gate rules), see `PROJECT_CORE.md`. For behavioral rules, see `CLAUDE.md`.

**How to use this file**: before starting a session, read `PROJECT_CORE.md` (esp. §2.1 DATA FLOW) + `CLAUDE.md` + this session's row only. You don't need the rows above it — just their **Output**, which now exists on disk; treat those files as given. Mark Status when you finish.

## Status legend
`todo` → not started · `in-progress` → partially done · `done` → deliverable exists and meets Acceptance · `blocked` → waiting on a dependency

## How this split works

Two rules drive the ordering, both aimed at keeping GPU time short and most work locally verifiable:

1. **CPU/GPU separation inside each module.** Every module is split into *decision logic* (pure functions over dicts/CSV rows — λ selection, gate predicates, resume state) and *execution* (loading a model, running inference). Decision logic is a CPU session with real unit tests; execution is a thin loop inside a GPU session. This is why `sweep.py` and `eval.py` land in Track C (CPU) even though they conceptually "need a GPU".
2. **Cached artifact handoff.** Each GPU session commits small reference artifacts into `tests/fixtures/` so downstream CPU sessions develop against real numbers without a GPU. See the Fixture column.

## Parallelizable

- **A3, A5** are independent of each other → either order, or concurrently.
- **A2, A2b** are pure asset work → any time after A1, in parallel with A3–A6. **A2c now depends on A5** (it runs the normalizer to produce the sensitivity report), so it is no longer a pure-human task and no longer the long pole it was before the word→digit decision.
- **C1, C2, C3, C4** only need Track A + `baseline.json` → all four are independent of each other.
- Serial bottlenecks: A1 → B1 → B2/B3 → D1 → D2.

## Open decisions

- ~~**Is `dataset/` tracked in git?**~~ **Decided: no.** `dataset/` is gitignored. Consequences, all handled in A1/B1: data reaches each platform out-of-band (Kaggle Dataset attachment, local copy, server mount); `data.dataset_path` is the single config field that differs per platform, so `src/` stays free of platform paths; `dataset/CHECKSUMS.txt` **is** committed and is the only mechanism proving two platforms ran on identical bytes. Provenance must record the checksum-manifest hash, not just the git commit — otherwise a run is reproducible in code but not in data.
- **Is `outputs/` tracked?** Still open. Recommendation: gitignore `outputs/**` but force-track the small text evidence (`provenance.md`, `metrics/*.json`, `metrics/*.csv`, `audit/*.csv`) and never the weights, `adapter/`, or audio. Otherwise the §0 Evidence-Based principle ("every claim has an artifact path") only holds on the machine that ran it.
- **Which OOD set?** §3 defaults to VIVOS and history compares against VIVOS 1.78%, but the field is swappable. A2 should record exactly which VIVOS split/subset is used so B2's number is comparable to the old repo's.

## Notes

- Track A + Track C (13 of 18 sessions) need no GPU and are fully verifiable locally. Only B1–B3, D1, D2 need Kaggle.
- **Tier 4's reference is post-edited PhoWhisper-small output** (§4 property 1). It flatters PhoWhisper checkpoints and penalises other families. Every tier-4 number reported anywhere must carry that caveat, and `provenance.md` should record the reference version so a future independently-transcribed set can be compared against it.
- More real audio is expected over time. When it lands: **extend** `real_bench_path`, keep the original ~40 min as a frozen slice so past runs stay comparable, and record the split in §4. Do not silently replace the benchmark — that invalidates every historical tier-4 number.
- If a session's Acceptance can't be fully verified in the environment you're in (e.g. no GPU), say so explicitly rather than marking `done` — same rule as "test UI features in a browser, don't just claim success".
- `tests/fixtures/` is committed. Keep it small: `delta_stats.json` records the real Δ's shapes/rank/norms, but the Δ tensors themselves are never committed (`synthetic_delta.pt` from A6 carries the structure at toy dimensions instead).
- `unpaid-dataset` / `dataset_by_task` / `done` are copied in A1 but unused until someone runs the pipeline against them — the profiling gap in `CLAUDE.md` still applies, and each needs its own §4 metadata block before its numbers mean anything.
